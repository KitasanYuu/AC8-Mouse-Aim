# AC8 MouseFlight

为 **ACE COMBAT 8 离线单人模式**提供鼠标指向飞控、独立跟随相机和方向指示。

移动鼠标指定一个世界方向，飞机通过俯仰、滚转和偏航输入尝试对准它。目标是提供类似“鼠标指向、飞机追随”的操作方式，而不是改变游戏的飞行模型。

> 仅供离线单人使用。不支持多人模式，也不保证与其他相机、输入或加载器模组兼容。游戏更新后，旧版本模组可能不再适用。

## 当前状态

- 当前版本：**0.2.30**，性能专项第一、二阶段；最新安装包为 **共存安装器 r1**，游戏内代码未变。
- 目标环境：Windows x64，ACE COMBAT 8 Steam Build **25201480**。
- 依赖仓库内随附的 RE-UE4SS；原生模块会校验加载器版本及游戏关键签名。
- 已完成构建与有限的协议、数学和状态模拟检查；新版性能收益及不同硬件兼容性仍需实机反馈。

本项目为非官方模组，与游戏开发商、发行商及 War Thunder 无关联。

## 功能

- **鼠标指向飞行**：目标方向保存在世界坐标中，飞机按 War Thunder 式升力矢量规则追随：先滚转使目标位于座舱上方，再拉杆。不设防撞地、防失速等限制，完全执行玩家指向；低空快速下沉时只改变到达方式（不用推杆去够侧上方的瞄准点，改为滚转后拉杆），瞄准点仍完全由玩家决定。规则见 `docs/maneuver-spec.md`。
- **到位制动与改平**：结合机体角速度抑制过冲，在接近目标后逐渐改平。
- **独立跟随相机**：相机平滑朝向目标，保留游戏原有视野角度变化。
- **方向指示**：分别显示鼠标目标与实际机头方向，采用半透明标记。
- **键盘临时超控**：WASDQE 对应的手动轴输入优先，不必关闭鼠标模式。
- **自由观察**：按住 F 环绕观察，飞行目标不变；松开后相机平滑返回目标方向。
- **暂停处理**：游戏暂停时冻结鼠标目标，恢复后将目标重新置于屏幕中心。
- **原生注视与演出让出**：识别长按注视及已验证的演出相机激活状态，暂时让出相机和操控，结束后恢复。
- **可选性能统计**：记录模组工作耗时和帧间隔，辅助排查卡顿。

模组修改玩家操作输入和相机视角，不修改气动、推力、武器伤害或存档数据。

## 安装

所有操作都通过仓库根目录的 **`AC8MouseFlight.cmd`** 完成。它会通过 Steam 的安装记录自动找到游戏（找不到时才让你手动选择），打开后是一个菜单：

```text
==== AC8 MouseFlight ====
游戏目录：...\steamapps\common\ACE COMBAT 8
状态：已安装，离线 MOD 模式
Steam 启动参数：已设置

  1  更新 / 修复
  2  切换到联机原版模式
  3  复制 Steam 启动参数
  4  卸载
  0  退出
```

1. 完全退出游戏，下载（或 `git clone`）本仓库。
2. 双击 `AC8MouseFlight.cmd`，选择 **1 安装**。
3. 设置 Steam 启动参数（只需第一次）。安装结束时如果检测到还没设置，会自动把参数复制到剪贴板：Steam 库 → 右键 ACE COMBAT 8 → 属性 → 通用 → 启动选项，粘贴：

   ```text
   cmd /d /c "set EOS_USE_ANTICHEATCLIENTNULL=1&& %command% -anticheat_settings=AC8MouseAim_Offline.json"
   ```

   若原来有其他启动选项，请先备份。工具只读取 Steam 设置来判断是否已填写，不会修改它。

4. 从 Steam 启动游戏，选择“专家”飞行操作，进入单人任务。建议使用无边框窗口模式：方向指示使用桌面透明覆盖层，独占全屏下可能不可见。

**更新**：拉取最新代码后再运行 `AC8MouseFlight.cmd`，选择 **1 更新**。你在 `config.ini` 的 `[control]` 中改过的设置（如灵敏度、镜头跟随速度）会自动保留；输入槽位和轴符号等版本适配项按新版本重置。

**游戏目录里不放多余的东西**：游戏目录中只有 MOD 本身（`Game/Binaries/Win64` 下的加载器、UE4SS 框架和 `UE4SS/Mods/AC8MouseAim`）以及 `EasyAntiCheat/AC8MouseAim_Offline.json`。工具、脚本和备份都留在仓库目录，备份在仓库的 `backups/`。旧版本放在游戏根目录的脚本和备份文件夹，会在安装或更新时自动移到这里。

工具会校验复制后的关键文件；校验失败时应检查安装，而不是关闭保护。已有其他 MOD 或 UE4SS 时的处理见下节。

### 与其他模组共存

共存安装器不再一概拒绝已有 UE4SS：

| 已有环境 | 处理方式 |
| --- | --- |
| 没有框架或冲突加载器 | 安装随包 UE4SS 和本模组 |
| 已验证的兼容 UE4SS、默认 Mods 路径 | 保留框架、加载器、设置和其他模组，仅安装本模组并合并启用列表 |
| 运行库不兼容、多个运行库、自定义路径或重定向 | 写入前停止并说明原因，由用户手动整合 |

兼容性按运行库校验值判断，而非仅比较版本名称；目前只自动支持 `Game/Binaries/Win64/UE4SS` 布局下已验证的运行库。复用模式不会修复、替换或重新启用已有加载器，原有框架必须能够正常工作。

安装前备份保存在仓库的 `backups/`。其他模组的启用状态及顺序保留，本模组条目合并到列表末尾；`mods.json` 的格式化可能变化，但其他字段和值保留。

这解决的是安装层面的共存，**不保证功能层面无冲突**。同时修改玩家输入、相机或相关钩子的模组仍可能互相干扰。

## 操作

| 输入 | 功能 |
| --- | --- |
| 移动鼠标 | 改变飞行目标方向 |
| 按住 F | 自由观察；鼠标只改变观察方向 |
| 松开 F | 相机平滑返回飞行目标方向 |
| W / S | 临时接管俯仰，同时暂停自动滚转 |
| A / D | 临时接管滚转 |
| Q / E | 临时接管偏航 |
| F8 | 开关鼠标辅助模式 |
| F9 | 将目标方向重新对准机头 |
| F10 | 重新读取配置，并重新对准机头 |
| F7 | 开关方向指示层，不关闭飞控 |
| F4 | 开关逐帧飞行记录，用于反馈摇晃、过冲等手感问题，默认关闭 |
| F5 | 开关轻量性能统计，默认关闭 |
| F6 | 开关详细相机状态采集，仅用于专项排查 |

自由观察期间，目标保持原来的**世界方向**，而不是固定在屏幕坐标上；飞机仍会尝试朝该方向飞行。自由观察支持水平环绕，俯仰限制为 ±89°。

模组不会屏蔽游戏原有的 F 键绑定。如果发生冲突，请调整游戏键位。WASDQE 超控检测也使用这些固定按键。

### 注视与剧情演出

手动注视需要持续按住约 0.35 秒才触发让出，短按切换锁定目标不会立即退出鼠标模式。该时间是模组的防误触门槛，不代表游戏内部阈值。

注视或已识别的演出期间，模组隐藏指示、冻结鼠标目标并放行原生操控和相机。结束后保留约 0.25 秒缓冲再恢复。当前已验证 `ImpactCamera` 激活路径，但不能保证覆盖所有剧情相机。

## 配置

安装后的配置文件：

```text
Game/Binaries/Win64/UE4SS/Mods/AC8MouseAim/config.ini
```

最常用的设置是鼠标灵敏度：

```ini
[control]
sensitivity=0.10
```

数值越大，移动相同鼠标距离时目标转动越快。修改后可按 F10 重新加载。

配置中部分 `gain`、`damping` 等字段为历史兼容项，并不用于调整当前控制器。请不要把所有字段都当作有效的手感参数。轴符号和输入槽位属于版本适配设置，正常情况下不应修改。

## 性能与问题反馈

### 0.2.30 的优化范围

- 用进程内数字接口替换实时文本管道和相机目标文件。
- 同帧传递姿态与目标，不积压过期帧。
- 原生日志由后台线程写盘，使用有容量限制的队列；繁忙时丢弃诊断信息，而不是等待写盘。
- 输入钩子提前排除非玩家调用，减少重复键盘查询。
- 复用逐帧脚本中的部分读取和转换结果。

**没有降低指示层刷新率，也没有改变其绘制方式。** 飞控参数、相机位置及平滑参数保持不变；通信延迟减少后，响应可能比旧版更及时。

这些改动针对模组自身的开销，不保证消除游戏资源加载、GPU 瓶颈或其他软件造成的全部卡顿。

### 如何提供有用的卡顿记录

1. 进入容易复现问题的任务，按 F5 开始统计。
2. 正常游玩，经过一次明显卡顿或敌人刷新事件。
3. 再按 F5 结束统计，提供最新的 `MouseAim-xxxxx.log`。

统计约每 10 秒汇总，关闭时补报剩余数据。**不需要同时开启 F6**；F6 是更详细的相机状态采集，会产生额外文件操作。

日志位置：

```text
Game/Binaries/Win64/UE4SS/Mods/AC8MouseAim/Logs/MouseAim-xxxxx.log
Game/Binaries/Win64/UE4SS/UE4SS.log
```

提交 Issue 时建议附上：

- 模组版本、游戏版本。
- CPU、GPU、内存、游戏所在存储设备类型。
- 分辨率、显示模式，以及是否使用其他模组。
- 具体任务和触发情况：持续掉帧、单位刷新卡顿，还是相机/标记视觉顿挫。
- 相关日志；如已有未加载模组时的对照结果，也请说明。

`script_wall` 包含 `native_bridge`，两者不能相加；`frame_gap` 包含游戏其他工作，不等同于模组耗时。统计不测量 GPU 时间，也不能单独证明卡顿原因。

> F8 只停止鼠标辅助，不会卸载模组。关闭 F8 不能作为“完全原版”的性能基线。

## 已知限制与排查

- **游戏更新后失效**：本项目包含版本相关的输入与相机适配。请先禁用模组，等待对应版本支持。
- **看不到方向指示**：检查 F7 状态，并尝试无边框窗口模式。剧情注视或暂停时隐藏标记是预期行为。
- **启动失败、黑屏或崩溃**：退出游戏，先用 `AC8MouseFlight.cmd` 切换到联机原版模式；反馈游戏版本和日志，不要混用不同版本的文件。
- **部分演出未正确让出**：当前状态检测并非覆盖所有演出。请说明任务和触发位置，再按需采集 F6 记录。
- **其他模组冲突**：尤其是输入、相机、覆盖层和共用 UE4SS 的模组，不保证兼容。
- **新版性能待验证**：自动检查不等于实机兼容性或性能验收，欢迎提供可复现反馈。

## 停用、回退与卸载

### 切换到联机（原版）模式

退出游戏，运行 `AC8MouseFlight.cmd`，选择 **2**，在「离线 MOD」和「联机原版」之间切换：

- 切到联机原版：停用 `dwmapi.dll` 加载器，并提醒你在 Steam 启动选项中清空本 MOD 的离线参数。这会停用共用该加载器的所有 MOD；其他类型的加载器不在处理范围内。
- 切回离线 MOD：重新启用加载器；如果 Steam 启动参数还没填，会自动复制到剪贴板。

进入多人模式前务必退出游戏，完成切换并清空启动参数；F8 不能代替这一步。项目不提供任何联网兼容性或账号安全保证。

### 回退版本

退出游戏，把仓库切回需要的版本（例如 `git checkout <提交或标签>`），再运行 `AC8MouseFlight.cmd` 选择 **1**。

### 卸载

退出游戏，运行 `AC8MouseFlight.cmd`，选择 **4 卸载**，然后在 Steam 启动选项中清空本项目的离线参数（检测到仍有该参数时会提醒）。

卸载只移走本 MOD 并移除它的启用项，保留其他 MOD。如果没有发现其他 MOD，会询问是否同时移除 UE4SS 框架和加载器，让游戏目录恢复原样。移走的文件都在仓库的 `backups/` 中，可以恢复。

**卸载本模组不等于禁用所有模组。** 其他模组仍可能加载，进入多人模式前需要单独确认。

## 开发说明

目录结构：

```text
AC8MouseFlight.cmd    用户入口：安装/更新、模式切换、启动参数、卸载
tools/                AC8MouseFlight.cmd 的实现
Payload/              装进游戏目录的文件（Lua 脚本、配置、DLL、UE4SS）
src/                  原生输入处理、飞控、相机修正、指示层及诊断
tests/                飞控数学检查、闭环仿真、Lua 相机数学检查
docs/maneuver-spec.md 机动范式规范（飞控行为以此为准）
dev/                  开发脚本：构建、检查、调试同步、飞行重建、飞控对比台
```

构建需要 Visual Studio 2022 的 MSVC x64 C++ 工具链、Windows SDK、Git 和网络连接。`dev\build.cmd` 会先运行 `dev\Setup-Dependencies.ps1`，将 RE-UE4SS 固定在 `e3ba1016562d6c0868c410d0a71e88bfcdbf691b` 提交。源码保存在忽略提交的 `deps/ue4ss-source/`，后续构建可离线复用。构建不需要编译或替换随附的 UE4SS.dll。

```bat
dev\build.cmd
dev\check.cmd
dev\check_lua.cmd
```

构建产物为 `build/ac8_mouse_aim_010.dll`，并复制到 `Payload/Game/Binaries/Win64/UE4SS/Mods/AC8MouseAim/Scripts/`。DLL 文件名保留历史命名，不代表版本。`check.cmd` 运行 C++ 飞控数学检查和闭环仿真；`check_lua.cmd` 用固定的 LuaRaw 源码编译 Lua 工具，检查全部 Lua 脚本的语法与相机数学。上述检查不能替代游戏内验证。

### 开发调试同步

退出游戏后，在项目目录运行一次：

```bat
dev\Dev-Deploy.cmd -GamePath "D:\SteamLibrary\steamapps\common\ACE COMBAT 8"
```

若目标目录尚未安装本模组，脚本会在构建后完成首次安装；如果已有其他来源的 UE4SS 或加载器，安装保护仍会拒绝覆盖。首次安装后，仍需手动设置上文的 Steam 离线启动参数。后续直接运行 `dev\Dev-Deploy.cmd`：它会记住本机游戏目录，先构建 DLL，再只同步内容发生变化的 DLL 和 Lua 脚本。安装后的 `config.ini` 默认保留；需要同步仓库配置时显式加 `-IncludeConfig`。只修改 Lua 时可用 `-NoBuild` 跳过 C++ 构建；`-Preview` 根据当前 Payload 列出将更新的文件，不进行构建。

调飞控时不必重启游戏：

- **调参数**：修改已安装 `config.ini` 的 `[tuning]` 段并保存，运行中的游戏约 0.5 秒内自动重新读取。
- **改飞控逻辑**（`src/maneuver.h`、`src/flight_logic.h`）：游戏运行中执行 `dev\Dev-Deploy.cmd -Live`。它构建并替换开发用的 `ac8_flight_logic.dll`，游戏约 1 秒内热加载，日志记录 `flight logic: hot-loaded generation N`。接口不兼容时拒绝加载并保留当前逻辑。修改钩子、桥接、Lua 或 `LogicInput`/`LogicOutput` 结构仍需退出游戏后正常同步。
- **逐帧记录**：按 F4 开关，日志中的 `TRACE` 行包含误差、角速度、线性杆量、实际写入值和键盘接管状态。

### 实时飞行重建

`dev\Telemetry.cmd` 启动一个本地小服务（只用 Python 标准库），并在浏览器打开 `http://127.0.0.1:8731/`：

- 游戏中实时重建飞行：三维追尾视角（机头、速度方向、目标方向、轨迹）、俯视航迹、速度/高度/攻角/侧滑/过载/角速度、杆量与加速/减速输入，以及最近 20 秒的曲线。
- 敌机：每秒 10 次记录附近飞机（最多 1000 架，大混战分几个包发送）的位置、姿态和速度，以及游戏自己的锁定候选标记（可锁定、暂不可锁定；友军不可锁定，据此区分敌我）；大型机的可锁定部位（Tu-95 机翼和炮塔、LADON 引擎、Moon 11 的磁轨炮等）只在被选中时记录。头目、头目的护卫无人机和精英（Shadow 等）另以约每秒 30 次记录，LADON 还记录可变后掠翼的后掠和下折角。当前选中的目标高亮并显示距离、接近速度、高度差和航向夹角；同时记录游戏自己给出的本机速度，用于核对计算值。
- 每次飞行自动录制到仓库的 `recordings/`（不纳入 git），页面左上角可选择录像回放、拖动和变速播放。录像也用于拟合整机模型。

需要在游戏目录的 `config.ini` `[control]` 中设置 `telemetry_port=49731`。MOD 每帧向 127.0.0.1 发送一个 UDP 数据包，不等待、不阻塞，没有服务接收时直接丢弃；设为 0 即关闭。

### 飞控对比台

**运行时粗模探针（实验性）**：遥测开启时（`telemetry_port` 非 0，即录数据时）自动采集，不占按键：每种玩家机体出场 5 秒后采一次，LADON 和 Moon 11 第一次出现时各采一次。模组对当前机体和已出场的头目执行只读采集，并在游戏安装目录的 `Game/Binaries/Win64/UE4SS/Mods/AC8MouseAim/Scripts/` 写出 `mesh-probe-*.json`。文件记录组件、网格引用、相对变换、网格边界、骨骼位置，以及反射层可读取的碰撞形状；不会读取或解包游戏资源包。每次采集是一次性的，不参与每帧飞控。`dev/compare/build_model.py <mesh-probe-*.json>` 从采集结果提取机体网格的包围盒和骨骼铰点，写成 `dev/compare/models/probed_<机型>.js`，`models.js` 按常规战斗机模板在这些实测点上生成玩家机体粗模（预览：`dev/compare/models_preview.html`）。实测 Su-35 的 25 个机体骨骼、LADON 本体的 51 个骨骼和多个部件可读，但没有取得可用碰撞凸包或表面顶点。对比页在 Su-35 条件下使用 `dev/compare/models/su35.js`（实测骨骼点定位，外缘为推定）；其他机体和敌机用 `models.js` 里的粗模。LADON 粗模按设定图和游戏截图搭建：固定机身、展开时的窄翼和收起时近似 XB-70 的大后掠，只有外翼下折，回放时按实录的后掠角切换。另有一版按骨骼点推定的 `dev/compare/models/ladon.obj`（米制，X 向前、Y 向右、Z 向上）。敌机的回放姿态来自实录（头目高频）。它们不是游戏原始网格；若要得到原始表面，仍需研究运行时渲染网格的 CPU 可访问性。

`dev\compare\compare.cmd` 让几种飞控在同一个整机模型上飞同一组场景，并打开 `dev/compare/index.html` 横评（没有基准，各飞控之间互相比较）。有敌机的场景由同一个虚拟飞行员做同样的决策，所以差别只来自飞控本身；每个场景都在三种机体上各飞一遍。

- 页面分“场景”和“总览”两页。场景页顶部是横评表：行是飞控，列是三种机体下该类场景的关键指标和综合代价，每列按名次着色（绿好红差），✕ 表示坠地。下面是一个三维画面，所有飞控的飞机和敌机在同一个画面里（有敌机的场景默认真实比例的追尾视角，地面是零高度上 1 km 的固定网格，速度感与飞行重建一致；镜头也可选全局或跟随目标；只看方向的场景默认全局并把飞机横向错开），每个飞控一个姿态仪（地平线、瞄准点相对机头的位置、读数、杆量）。多机缠斗场景里，每个飞控当前锁定的敌机外有该飞控颜色的方框，标着它将是该飞控的第几个击落；击落处留下该飞控颜色的 X 和序号；被所有飞控都击落的敌机不再画模型和航迹，只留这些标记。目标多于 12 架时不显示普通敌机的名称；全局视角的取景在敌机进出时平滑过渡（也只在多机缠斗里）。再下面是整段时间轴，每个飞控一条色带（偏差角、坡度、滚转杆，白色竖线是击落），点击跳转；最下面是光标前后 10 秒的偏差角和坡度曲线。总览页是全部场景 × 机体 × 飞控的综合代价矩阵，带平均名次和第一名次数，点击一行打开该场景。
- 机体模型来自录像：姿态响应（延迟、游戏输入平滑、响应曲线、权限、滚转上限、高G、方向舵）、航迹（速度方向滞后机头、重力），以及按速度分段实测的权限和满油门加速度。机体：差机体、Su-35、Su-57、ADF-X02、迟钝机体（差机体延迟 ×1.3、权限 ×0.75）。拟合脚本 `dev/compare/fit_airframe.py`；按速度分段的拉杆、滚转和满油门加速度用 `dev/compare/fit_speed_tables.py --aircraft <机型> <录像>` 拟合，每档代表该 100 m/s 区间的中心速度。ADF-X02 极速约 850 m/s，能跟上 LADON 一阶段的速度，Su-35 和 Su-57 约 800 m/s 跟不上。
- 场景只有 3 类、21 个，统一命名为“类别 · 内容”，编号为“类别缩写_两位序号”。只保留覆盖不同行为所需的最少场景：排名与其他场景几乎一致、或已被录像空战覆盖的场景（单机追踪、脚本追击、连续换目标等）都已去掉。
  - 通用机动 `man_`（12 个）：捕获右 3°、右 90°、右后 150°、下 15°；滚转中逆向和机腹方向换目标；平飞保持、鼠标微调；低空大坡度俯冲中瞄准点上抬（复现 Moon 11 撞海时的情形）；以上定义在 `harness.cpp`。另有 M28 的三次战时降落：盘旋进近、垂直俯冲、高速俯冲（`extract_landings.py` 从录像截取，存在 `landings/`）。
    - 跑道由录像里所有地面滑跑拟合；每个飞控从录像的同一状态出发，瞄准点取录像航迹上 1.5 秒后的位置，速度、油门和减速板按录像。直接重放录像里的瞄准点不行：对比台的航迹 20 秒会偏出几十米，谁都落不到跑道上。
    - 成功降落的标准取三次录像接地时的包络：下沉 ≤ 15 m/s、坡度 ≤ 15°、俯仰 ≥ -3.5°、离中线 ≤ 40 m、航向偏差 ≤ 10°（两个方向都算）、落在跑道长度内；没触地就到了时间也算失败。
  - 多机缠斗 `multi_`（5 个）：Shadow 四机；M28 千颗亮点的大混战（98 架，其中 78 架 Tu-95）按 4 种固定击杀顺序各跑一遍。
    - 目标这么多时，若让虚拟飞行员按各自位置挑目标，约 10 秒后各飞控就打的不是同一批了，击落数里混进了选目标的运气。所以同一场景里所有飞控按同一个固定顺序打，前一个被击落或离场才换下一个。
    - 4 种顺序：实战顺序（你实际交战过的 29 架，即锁定期间接近到 3 km 内的，从你录像里的起点出发）；以及距离优先、偏角优先、综合三种。后三种由一个与参评飞控无关的理想化点质量追击者（航迹直接以 12°/s 转向瞄准点）自由选目标飞一遍得出。
    - 参考飞行转得慢，是为了让顺序的节奏所有飞控都跟得上：用 35°/s 时，某个飞控在一个目标上慢几秒，后面的目标就远出几公里，越落越多（同一顺序 21 架对 45 架）。
  - 头目战 `boss_`（4 个）：LADON 一阶段、LADON 二阶段（含库尔比特）、Selene（Moon 11，护盾阶段与缠斗）、Shadow 22（M28 最后一架 Shadow）。
  - 后两类的敌机轨迹取自录像（只取敌机，不用录像里玩家的操作），清单写在 `dev/compare/scenes.txt`，每行“类别 文件 编号 [start=<米>] [order=game|near|nose|mixed] 标题”。
- 有敌机的场景：我方从敌机后方的标准位置出发（多机 1.5 km、头目 800 m 并取头目当时的速度；`scenes.txt` 可用 `start=<米>` 改起始距离）。虚拟飞行员选目标、压机炮提前量、按距离跟速（对头目保持约 400 m，其他 700 m，目标急减速时提前减速）、管高G、低空拉起；导弹与机炮按简化规则判定，敌机按录像轨迹飞、不对模拟中的飞机做反应。多机比较击落数、全部击落用时、选定到开火和机炮瞄准，精英（如 Shadow）只有 1 km、5° 内发射的导弹才命中且要两发；头目不计击落，也不会因距离远而放弃追击，比较保持锁定和机炮瞄准的时间（画面里 LADON 周围画出 1 km 的 ECM 范围球，有飞机在内时变为实线）：LADON 的 ECM 使导弹只能在 1 km 内锁定，CIWS 拦截导弹；Moon 11 在 2 架以上护卫无人机位于 150 m 内时有护盾，她和无人机都不受伤害，虚拟飞行员这时不攻击她们。
- 截取录像：`dev/compare/extract_battles.py`（整段空战，`--window <录像名>:<起>-<止>` 指定；`--boss ladn_CP_C --only-boss` 用于 LADON 这类靠部位锁定的头目；敌我按录像里的锁定候选标记区分，Tu-95 机翼等可锁定部位并入机体），存到 `battles/`，再在 `scenes.txt` 里加一行。单个敌机片段仍可用 `dev/compare/extract_tracks.py` 截取（`scenes.txt` 的 `single` 类），目前不使用。
- 参评飞控：本仓库工作区（`src/` + Payload 的 `[tuning]`）、本仓库按游戏里现装的 config.ini（仓库根目录的 `.dev-game-path` 指向游戏目录时）、主仓库 0.2.30 与 0.2.35、xsd467 pw5。其他仓库的源码按提交原样放在 `dev/compare/controllers/<名称>/`（只改命名空间），适配器见同目录的 `.h`；新增飞控时照此添加并在 `harness.cpp` 注册。
- 试参数：`dev\compare\compare.cmd "variant=kd 0.1:pitch_kd=0.1;level_per_deg=10"`，会作为额外一列与当前配置并排。
- `dev/compare/scorecard.txt` 随仓库提交，改飞控后重跑，用 git diff 看各场景分数的变化。

`ac8_flight_logic.dll` 仅用于开发，不在 Payload 中；正式安装使用主 DLL 内置的同一份逻辑代码。

每次同步前的文件保存在忽略提交的 `build/dev-backups/`，可运行 `dev\Dev-Deploy.cmd -Rollback` 恢复最近一次同步前的版本。调试同步要求游戏已退出，并校验已安装的 UE4SS 和加载器；它不重装框架，也不修改 Steam 启动选项。切换多人前仍按上面的模式切换步骤操作。
